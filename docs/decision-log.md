## 一、开局:栈与定位(2026-09-08~10)

### D1 训练框架:自建 → verl → slime
- **背景**:要做 DSH(Qwen3.5)多轮 agent RL,先得选训练栈。
- **备选**:自建 AgentLoop/网关(最初路线)→ verl+AGL → slime。
- **裁决**:钉住 slime `4c193f1f`,vendor 零修改,接缝全部放项目内 `slime_dsh/`。
- **依据**:实测否决链——AGL 代理对流式请求直接返回 400(真实 DSH 请求重放证实,不是看文档
  猜的);自建管线被用户叫停("先看别人实现,不自写");slime 是 GLM-5 官方后训练基础设施、
  唯一原生 OPD、CPU 侧全部验证(64 上游测试+真实 DSH SDK 协议检查)。
- **验证**:DSH 生命周期检查 7 passed;钉住树未漂移。

### D2 模型与路线:dense 9B 主线,LoopLM 降为限额臂
- **背景**:最初设计自研 loopify(层共享手术)student,用户纠正"LoopLM 是现成的 Ouro 族,
  最重要的是调研,不要意淫"。
- **备选**:自研 loopify-9B / Ouro-2.6B 作 student / 纯业界复制 dense 9B。
- **裁决**:主线=纯业界复制(dense Qwen3.5-9B 三段:SFT→GRPO→OPD);LoopLM 循环层降为
  加分实验臂(≤8 GPU·h 试点,恢复 <50% dense 参照即止损封存)。
- **依据**:我们实测的硬数据支撑了这个排序——硬绑层共享无恢复训练完全崩塌
  (HumanEvalPlus 96.9%→0%),而简历项目的主线必须先保证可交付。
- **验证**:阶段①已按此主线交付完成。

## 二、阶段① SFT 的四个选择(2026-09-10~12)

### D3 SFT 数据格式:单格式 Klear,不混池
- **备选**:A) Klear-66k 单格式(官方用法);B) 27B teacher 在 DSH 内自产轨迹;C) 三格式混池。
- **裁决**:A。
- **依据**:PIPE(arXiv 2602.01611)证明轨迹-SFT 收益大头是"接口熟悉度"且跨接口不迁移;
  Klear 官方就是单格式训+评;C 无文献支持。B 留作环境就绪后的增强(成本高)。
- **验证**:验收时专门测了跨格式迁移——OpenHands/R2E 切片 NLL 只降 6%/2%,同格式 held-out
  降 33%。**格式特异性被我们自己的数据证实**,反过来支持了阶段②直接在 DSH 格式上做 RL 的决定。

### D4 数据清洗:规则过滤,不过度工程
- **裁决**:Qwen3CN 三条规则(缺终止信号/失败任务/畸形工具调用剔除)+ GLM-5 错误段掩码思想,
  69,705→28,208 条。
- **依据**:SWE-Prime(10% 精选>全量)+TR 同款做法;不引入模型打分器(阶段①不需要第二个模型)。

### D5 训练量:1 epoch,不赌
- **裁决**:用户钉死 1 epoch=step 500 检查点;job 配 2 epoch 到点外部停。
- **验证**:持平基线(HumanEvalPlus 31/32 同题失败)、NLL −33%、A/B 解决率 15%→30%、
  提交纪律 10%→100%。**教训也如实记录**:停训 watcher 等错目录名(0 索引 iter_0000499),
  多跑 63 分钟——监控命令含被清理路径字符串被自己扫掉的二次事故,一并入档。

### D6 评估工具:自写胶水必须过金标准
- **背景**:钉住的 vLLM 0.19.1 已删官方 perplexity 工具;lm-eval 不支持 slime 掩码的多轮
  assistant-NLL。
- **裁决**:走 prompt_logprobs(文档化路径)自写,但**必须用 HF 前向(训练栈同款 transformers)
  逐行对拍**才算数。
- **验证**:8 行×2 模型 max|diff|=5.9e-4<5e-3,数字可信。4 个评估 bug 全部复盘入档。

## 三、阶段② 准备:环境、任务、格式(2026-09-09~12)

### D7 任务环境:训练走本地受限进程,官方评估走官方 harness
- **背景**:平台 Docker 层有缺口(docker-proxy 探针失败);官方 benchmark 强制官方容器。
- **裁决**:两条线分开——训练用自建本地 venv 沙箱(2026-09-09 用户授权,所有成绩标注
  自建协议);SWE-bench Verified 官方评估等平台层解决,不用自建评测器冒充官方。
- **依据**:用户规则"容器问题在平台层解决,不得自建替代评估器";KAT-V2.5 后来用数据
  背书了这条线(环境可靠性 16%→<2% 决定训练成败)。
- **验证**:LocalProcessSandbox 9/9 测试;RL 后端金标=1.0/空=0.0 集成测试过。

### D8 任务池先冻结、先排重
- **裁决**:rl-task-freeze-v1:独立复算排除(61 旧审计 blocked+20 held-out,SWE-bench
  Verified/full-test 零交集);确定性顺序+sha256。
- **依据**:防泄漏是硬纪律(Qwen3CN/LEGO-RL 同款);冻结让后续实验可归因。

### D9 RL 格式:直接上 DSH,不绕 Klear 中间格式
- **裁决**:用户拍板阶段② rollout 直接 DSH 格式。
- **依据**:DSH 是简历差异化点;接受初期解决率低的风险(D3 的跨格式数据说明 SFT 不覆盖
  DSH 接口);NeMo-RL pivot 式格式前教学留作补救后备(先测量后加码,见 D11c)。

## 四、奖励设计:七轮调研的裁决链(2026-09-11~12,本项目思考密度最高的一段)

### D11a 核心信号:二值测试通过
- **备选**:二值 / 测试比例部分分 / 相似度奖励(Meta SWE-RL 用补丁相似度,免环境)。
- **裁决**:二值(F2P 全过+P2P 不回归,金标评测器)。
- **依据**:五家 2026 TR(Qwen3CN/GLM-5/DSV4/K2.5/M2)+六家开源实现(slime 官方/DeepSWE/
  NeMo-RL/SkyRL/LEGO-RL/OT-Agent)核心一致;SWE-RL 相似度路线是免环境的规模化选择,
  我们有环境,不需要。
- **途中作废结论 1**:我曾据 4 个开源实现断言"纯二值是业界主流"——被用户驳回,扩大调研后
  修正:**大厂 TR 无一是纯二值**(全部有塑形层),正确图景是"可验证核+塑形",塑形密度随
  轨迹长度/算力上升。

### D11b 过程奖励 vs 惩罚:只罚不奖
- **备选**:PRM/步级正奖(AgentPRM/SWE-TRACE/PaTR 线,+5 SV)vs 规则化负向惩罚。
- **裁决**:负向惩罚(未完成罚+工具格式罚),无正向过程奖励。
- **依据**:①五家 TR 中四家塑形形态就是"只罚不奖",唯一做过程正奖的 MiniMax M2 系数未
  公开无消融;②风险不对称:规则罚不可 hack,正向过程奖需要打分器=新作弊面+装不下第二个
  模型;③**管线分工**:密集正向监督已分配给阶段③ OPD(teacher 逐 token KL,不依赖可 hack
  的奖励函数)——DSV4 同族;④ToolRL 消融:format 奖励前 ~30 步饱和→格式罚是短命机制,
  加退场条件。
- **KAT-V2.5 的对照**(事后):它用 PPO+critic 实现"逐步负反馈",证明同一目标可用不同
  机制达成;我们用 token 级 advantage 罚,不必引 PPO。

### D11c 部分分:争议项,v1 不用但挂重访条件
- **正方**:KAT-V2.5 Tier 3(失败轨迹给单测子集正分+检索 F2,SV 79.6%);AgenticQwen judge
  部分分。
- **反方**:受控实验 2605.02944(pass-rate 不可靠更优);LEGO-RL 明示无中间信用是局限但
  依然二值+难度筛选拿分。
- **裁决**:v1 不引入;**重访条件=难度筛选后组内方差仍过低**(大量 0/4 组)。
- **作废修正**:此前我说"没有 TR 做部分分",KAT-V2.5 推翻,已改"争议项"。

### D11d 噪声治理:三层机制、零代码优先
- **裁决**:首轮=slime 原生 DAPO 动态采样(零代码)+上游 abort 通道;v1 视崩溃率加装
  GLM-5 组修复(剔除+填充/丢弃)或 MiniMax M2.1 式 MIS+轨迹过滤。
- **依据**:零方差组浪费 rollout(DAPO 动态采样是 ScaleRL 获胜配方成分);GLM-5 崩溃剔除
  的 TR 原文;KAT 实证沙盒故障 16%→<2% 使训练崩溃降 10 倍——我们 qualification 日志的
  startup failure 率说明这不是理论风险。

### D11e 防作弊:基础设施为权威,代码拦截为兜底
- **裁决**:本地网络命名空间隔离=权威层(已天然满足);代码拦截四通道参照 AGL(git/网络/
  装包/测试篡改,拒绝必带指路反馈);环境准备剥 git 历史(KAT 同款)。

## 六、阶段③ OPD 的定位(已定,未实施)

### D14 OPD 不是叠加项,是整合段
- **裁决**:三段=「专家式 GRPO(阶段②)→ OPD 整合(阶段③)」,与 DSV4"混合 RL 被 OPD 取代"
  同族;teacher=Qwen3.5-27B 全程唯一。
- **依据**:DSV4 TR 是最强业界背书;token 级(slime 实现)vs 全词表(DSV4)取舍已评估
  (2-4 卡装不下全词表,接受 token 级+监控 Pass@k 风险);OT-Agent 的 teacher 发现
  (GLM-4.6 比 GPT 系好 2 倍)佐证 teacher 质量关键。

### D15 扩池路线:smith 出局,gym 扩仓库(2026-09-13)
- **背景**:难度筛选显示 curated 池 79% 零解、带内仅 12 任务,不够首轮;用户指令做 smith 扩池。
- **备选**:SWE-smith 59k 池 / gym 池扩仓库 / 放宽预算重筛零解任务。
- **裁决**:gym 扩仓库。smith 数据 schema 是 Docker 镜像绑定(无 base_commit/test_patch),
  与本地 venv 路线结构性不兼容;gym 剩余 2,066 eligible(pandas 722/MONAI 355/moto 333/
  mypy 255/dvc 221/modin 107/conan 73)完全管线兼容。
- **验证**:探针实证 mypy 9/12=75%、moto ≈83% 合格率(vs 原 curated 池 30%)——配方经
  7 轮迭代收敛;正式批 588 候选在飞(77.6%)。附带修复四处基建 bug(git safe.directory
  chown 信任链/绝对路径契约/env.sh 必须前置/残骸清理)与两个新机制(--repos 白名单、
  pytest_args 通道)。

### D17 奖励栈落地:四个实现裁决(2026-09-13,设计锁定后的执行)
- **背景**:D11f 锁定的奖励方案进入实现;设计文档 §3 列了四个模块与单测清单,
  但机制细节(挂载点组合、token 定位、拦截器机制)留到实现时定。
- **裁决与依据**(全部在锁定设计边界内):
  1. **未完成惩罚的实际集成点=all-samples-process 而非 custom_rm 路径**——实测
     agent 流里 reward 在 generate 内已设,rm_hub 只对 reward=None 的样本调 custom_rm;
     组修复钩子本来就在归一化前跑,惩罚顺路进同一钩子(custom_rm 保留为独立可用的
     slime 挂载形态)。
  2. **组归一化用 custom-reward-post-process 整体替换而非依赖上游默认**——读源码发现
     上游 reshape 依赖样本总数==K×batch,多分段 agent 轨迹恒不满足→退化为全批全局
     均值归一化;GLM-5 语义要求按组统计,自写钩子按 instance_id 分组并剔除环境崩溃。
  3. **格式罚 token 定位=字节级 BPE 精确对齐**(convert_ids_to_tokens+GPT-2 逆映射,
     逐 token 字节拼接与解码文本 utf-8 全等断言)——单 token decode 有替换字符问题,
     重编码不保证同 token 序;字节级对齐对 Qwen 族精确且有运行时断言兜底。
  4. **拦截器=adapter 回复层命令改写(违规→无害 echo 打印反馈)而非丢弃工具调用**——
     设计要求"agent 可继续任务而非直接终止";反馈作为工具结果回注即 Qwen3CN 原文行为
     的协议等价物;wire/manager 同源改写保证下轮 echo 匹配不 fork 训练 tokens 不受影响。
- **验证**:scripts/check_reward_stack.py 11/11 PASS(含真 tokenizer 对齐+loss_mask
  正交性+组统计剔除);实现中实测抓出并修复组归一化的局部/全局索引 bug。
- **边界**:所有系数/开关默认零/关、走环境变量——数值本体属 smoke 超参单(用户批前
  不进任何配置);格式罚启用需同步关 --normalize-advantages(白化会吃掉罚项)。
- **附带发现(如实入档)**:harness-check 3 lifecycle 用例自本地后端绑定起即失效
  (fixture patch 的 E2BSandbox 已死)——先存问题,git 对照验证非 D17 引入,待改 local 契约。
