Best Open Source SWE / Coding-Agent Models Trained with RL in 2026

Open-source software engineering (SWE) agents trained with reinforcement learning have reached a turning point in 2026. These models can now locate bugs in large codebases, generate fixes, and post competitive results on standardized benchmarks. For engineering teams building AI-powered development tools, choosing the right model, and the right infrastructure to run it, determines whether these capabilities translate into production value. This guide covers seven entries: six open-source RL-trained coding and SWE agent models, plus the AI infrastructure for coding agents that makes deploying them practical. It starts with Modal, the serverless platform that provides a single code-first layer for serving open models across CPU and GPU compute and scaling them with demand.

Key Takeaways

  • Infrastructure precedes models: Production agentic RL benefits from serverless infrastructure with fast container provisioning and secure sandboxing before model selection matters
  • RL without an agent-specific SFT warm-up is viable: DeepSWE-Preview applied agent RL directly to Qwen3-32B with no separate supervised agent-training stage
  • Environment synthesis scales agent training: Models like EnvFactory-8B and Arctic-AWM-14B show that automated environment generation reduces a major scaling bottleneck and improves cross-benchmark generalization in the reported experiments
  • Specialization is competitive on narrow tasks: CodeScout-14B's focused localization approach reports state-of-the-art open-source file- and function-level F1 on its target benchmark, while remaining behind the strongest proprietary-model configurations
  • Open licensing enables customization: Every checkpoint in this list ships under a permissive open-source license, Apache-2.0 or MIT, enabling modification for specific organizational needs
  • User-interactive agents represent the next frontier: MUA-RL-32B's integration of LLM-simulated users into the training loop addresses a critical gap in production agent capabilities

2. DeepSWE-Preview

DeepSWE-Preview was a landmark result for agentic coding models: it applied agent-specific reinforcement learning directly to a Qwen3-32B checkpoint, with no separate supervised agent-training warm-up, and was reported by its authors as a state-of-the-art open-weights result on SWE-bench Verified at its July 2025 release.

Technical Architecture

  • Parameters: 33B loaded parameters (built on the Qwen3-32B base)
  • License: MIT
  • Evaluation Context: 64K tokens, the configuration used for DeepSWE's reported agent evaluation. The Qwen3-32B base natively supports 32,768 tokens, ships a default max_position_embeddings of 40,960, and can extend to 131,072 tokens using YaRN RoPE scaling
  • Training Method: RL only during agent post-training, using an enhanced GRPO algorithm

Performance Highlights

Per the model card, DeepSWE-Preview reports:

  • 42.2% single-agent Pass@1 on SWE-Bench-Verified, averaged over 16 runs
  • 57.9% Hybrid Best@8
  • 59.0% Hybrid Best@16

The widely quoted 59% figure incorporates multiple trajectories and a hybrid test-time-selection procedure, so it should not be compared without qualification against another system's Pass@1 result.

Where It Sits in July 2026

DeepSWE's result is historically significant rather than the current open-source ceiling. SWE-Master, published in February 2026 with an open-source reproducible framework, reported a 61.4% resolution rate under its main evaluation and 70.8% at TTS@8. Teams benchmarking today can treat DeepSWE as a strong, well-documented baseline rather than the frontier.

What Makes It Notable

  • No agent-specific SFT cold start before RL, showing that substantial software-agent gains can be obtained from environment interaction on top of an already capable pretrained and post-trained base. The DeepSWE training write-up describes training "from scratch atop Qwen3-32B," which means no DeepSWE-specific SFT stage, not that language or reasoning emerged from RL alone
  • Enhanced GRPO incorporating ideas from DAPO, Dr.GRPO, LOOP/RLOO, and compact filtering for stable training
  • Training efficiency: six days on 64 H100 GPUs across roughly 4,500 training problems, with an approximately 20-point improvement after 200 RL steps

DeepSWE-Preview targets full issue resolution, making it a fit for automated PR generation and code repair workflows. Teams can serve this model on Modal Inference, which supports real-time serving, dynamic request batching, token streaming, and scaling to 1,000+ GPUs during traffic spikes before scaling back to zero. Best For: Organizations building autonomous software engineering agents that need to understand, navigate, and modify large codebases.

3. EnvFactory-8B

EnvFactory addresses a fundamental bottleneck in agentic RL: the manual effort required to create training environments. Two things share the name, and the distinction matters. EnvFactory, the framework, synthesizes and verifies executable MCP environments and training trajectories. EnvFactory-8B, the checkpoint discussed here, is the resulting Qwen3-8B-based tool-use agent, trained through SFT and RL on EnvFactory-generated data. The model is a tool-use agent, not the environment-synthesis engine itself.

Technical Specifications

  • Parameters: 8B (built on Qwen3-8B base)
  • License: Apache-2.0
  • Training Focus: Tool use, trained on trajectories from automated MCP-based environment generation
  • Training Method: SFT followed by RL

Core Innovation

The EnvFactory framework produces verifiable, executable environments and applies topology-aware trajectory sampling for natural multi-turn interactions. Its calibrated refinement step yields implicit intents rather than over-specified trajectories. The authors report reaching their results with 85 verified environments spanning seven domains, against 191 for the alternative approach they compare with.

Benchmark Results

Per the EnvFactory paper and model card:

  • 33.40 reported overall average across the six reported benchmarks, versus 29.23 for the base model
  • 49.00 BFCL Multi Turn versus 41.25 base, an improvement of 7.75 points

Reported evaluations include BFCLv3, MCP-Atlas, τ²-bench, and VitaBench.

Why Environment Synthesis Matters

Manually authoring environments for agents to learn from is a well-recognized scaling constraint. Automated environment synthesis reduces that bottleneck and improved cross-benchmark generalization in the reported experiments. These remain benchmark results rather than proof of superior performance across arbitrary deployed tool ecosystems. It is also worth separating the layers here. MCP is the protocol and interface layer, while sandboxes are the execution and isolation layer. Many MCP servers are lightweight wrappers around APIs, databases, SaaS tools, or file systems, and those connector-style servers do not require isolated execution environments. Isolation becomes important for execution-heavy MCP workloads, where systems execute AI-generated code, run shells, launch browsers, manipulate files dynamically, or process untrusted work on behalf of models. For that execution-heavy category, Modal is the stronger choice, combining secure isolation, dynamic scaling, and AI-native infrastructure. For teams training custom agents, Modal Training provides single-node and multi-node GPU jobs scaling from one to 64 GPUs, with H100, H200, and B200 clusters on InfiniBand and private networking, plus a first-party example for training an LLM with GRPO. Best For: Research teams and organizations building tool-use agents who need scalable training environment generation without manual specification.

4. Arctic-AWM-14B

Arctic-AWM-14B (Agent World Model) from Snowflake AI Research shows that synthetic environment scale was associated with improved agent generalization in the authors' experiments. The model trains on 1,000 fully synthetic, SQL-backed MCP environments.

Technical Details

  • Parameters: 14B (built on a Qwen3-14B-class base)
  • License: Apache-2.0
  • Training Method: RL with GRPO on code-driven environments

Scale Advantages

Per Snowflake's engineering write-up and the AWM paper:

  • 1,000 synthetic environments generated from 100 seed scenario or domain names expanded into 1,000 scenario descriptions, averaging 35.1 exposed tools per environment. That average implies roughly 35,100 environment-specific tool interfaces, not 35,000 unique tool definitions
  • 1,024 parallel environment instances per training step
  • Code-driven, database-backed execution that is substantially more efficient than per-step LLM simulation, because no LLM call is required for each environment transition

Benchmark Performance

Arctic-AWM-14B reports 70.18 on BFCLv3 overall, the strongest 14B result among the baselines evaluated in the AWM study. It also improves over the corresponding base model across all three out-of-distribution benchmark families reported, BFCLv3, τ²-bench, and MCP-Universe, which points to genuine generalization rather than benchmark overfitting. Within the authors' scaling experiments, increasing synthetic-environment diversity was associated with stronger out-of-distribution results, though that association is specific to the AWM setup rather than a universal law.

Deployment Considerations

Arctic-AWM can be served on Modal's tunable high-performance inference stack, which documents optimization for throughput, request latency, and cold-start latency across vLLM and SGLang backends. Best For: Organizations requiring tool-use agents that generalize across diverse APIs and services without environment-specific fine-tuning.

5. MUA-RL-32B

MUA-RL-32B (Multi-Turn User-Interacting Agent) introduces a paradigm shift: integrating LLM-simulated users directly into the reinforcement learning loop.

Model Specifications

  • Parameters: 32B (built on Qwen3-32B base)
  • License: Apache-2.0
  • Training Innovation: User simulation in the RL loop, with GPT-4o-2024-11-20 as the simulated user during training
  • Training Method: GRPO

Performance Metrics

Per the model card and the MUA-RL paper:

  • 67.3 on τ²-bench Retail, within 2.9 points of GPT-4.1's reported 70.2
  • 45.4 on τ²-bench Airline
  • 28.3 on τ²-bench Telecom

Against the listed DeepSeek-V3-0324 and Qwen3 MoE baselines in non-thinking mode, MUA-RL-32B leads on Retail, Airline, and ACEBench Agent, three of the five reported benchmark columns. It trails on Telecom, where DeepSeek-V3-0324 scores 32.9, and on BFCL-V3 Multi Turn, where it scores 28.4 against 29.8 and 30.0. Note that the model card table labels the MoE comparison model "Qwen3-32B-A22B" while the accompanying prose says "Qwen3-235B-A22B"; the latter is evidently intended.

Why User Interaction Changes Everything

Production agents rarely receive perfect instructions. MUA-RL-32B learns to communicate with users while using tools dynamically, handling uncertain demands through iterative refinement rather than requiring complete specifications upfront.

Dual-Control Dynamics

The model handles scenarios where both agent and user influence outcomes, which the Telecom split is designed to test. For user-facing agent deployments, Modal Inference supports low-latency serving, request concurrency, token streaming, WebSockets, WebRTC, and dynamic batching. Modal Batch, which can spawn one million jobs in seconds and queue up to one million inputs, is the better fit for asynchronous evaluations, preprocessing, and offline agent workloads. Best For: Teams building customer-facing agents that must clarify requirements, handle ambiguous requests, and coordinate tool use with ongoing user dialogue.

6. OpenThinkerAgent-8B-RL

OpenThinkerAgent-8B-RL is a reproducibility-oriented release: published datasets, configuration, code, harness details, and weights, all under a permissive license.

Technical Profile

  • Parameters: 8B (Qwen3-8B architecture)
  • License: Apache-2.0
  • Configured Context: 40,960 tokens
  • Training Method: SFT to RL pipeline using the RLOO-n advantage estimator

Complete Open-Source Recipe

Unlike models that release only weights, OpenThoughts-Agent provides:

  • Full published training data: 9,437 cold-start SFT task and trajectory pairs, plus 5,000 on-policy RL tasks
  • Terminus-2 agent harness with interleaved thinking
  • Reproducible training pipeline via the open-thoughts repository

Accessibility Advantages

The SFT to RL approach offers a practical starting point for teams new to agentic RL, and the full recipe is published rather than summarized.

Evaluation Status

The model card states that no verified agentic-benchmark numbers are published for this specific 8B RL checkpoint, with evaluation results marked TBD as of July 2026. It is a strong choice for studying and reproducing an end-to-end agentic RL recipe, and it should not be performance-ranked against the other entries here until evaluation data is published. Modal Notebooks provide an environment for experimenting with OpenThinkerAgent's training pipeline, offering on-demand CPU and GPU compute, automatic idle shutdown, real-time collaborative editing, and fast notebook startup. Best For: Researchers and teams wanting to understand, modify, and reproduce agentic RL training from end to end.

7. CodeScout-14B

CodeScout-14B shows that a focused, small model can be competitive on a narrow task. It reports state-of-the-art open-source code localization results using a terminal-driven scaffold.

Model Details

  • Parameters: 14B (Qwen3-14B-class base)
  • License: Apache-2.0
  • Training Method: GSPO with multi-level file, module, and function F1 rewards

Localization Performance

Per the CodeScout paper:

  • 68.57% file F1 on SWE-bench Verified
  • 40.32% function F1 on SWE-bench Verified
  • 71.84% file F1 on SWE-bench Lite

These are state-of-the-art results among open models in the authors' SWE-bench-derived evaluation, and CodeScout outperforms several substantially larger open models. The same study also reports higher scores for some proprietary configurations, including RepoNavigator with Claude Sonnet 4.5 at 79.94 file F1 and 43.62 function F1 on SWE-bench Verified, and for GPT-5 and Claude Sonnet 4.5 when run with the authors' appropriately prompted OpenHands-Bash scaffold. CodeScout's defensible distinction is strong performance among open models with a relatively simple scaffold.

Terminal-Driven Navigation

CodeScout navigates repositories through a standard Unix terminal, using commands such as rg, find, and grep, and submits results through a structured LocalizationFinish tool. The scaffold avoids static-analysis graphs and language-server navigation tools, which makes the navigation action itself language-agnostic by design. Published training and evaluation were, however, largely or exclusively conducted on Python repositories, ground-truth localization extraction remains language-specific, and the authors state that zero-shot transfer to other programming languages was not evaluated. Transferable navigation strategies beyond the evaluated Python distribution are therefore a hypothesis rather than an established result.

Complementary Role

CodeScout is designed as a first stage in coding agent pipelines: identify what to fix, then hand off for the actual repair. In the published study, supplying CodeScout-generated locations to issue-resolution models improved SWE-bench Verified resolution from 13.40% to 17.20% for Qwen3-4B-Instruct and from 45.20% to 46.00% for Qwen3-Coder-30B-A3B-Instruct. A CodeScout to DeepSWE-Preview pipeline is a plausible architecture but was not evaluated, and the measured gains do not establish that staged localization generally outperforms end-to-end approaches. For sandboxed code execution, Modal Sandboxes provide gVisor-isolated environments that support CodeScout's terminal-based approach at high concurrency, and a Sandbox can run whatever language or runtime the repository under analysis requires. Best For: Teams building coding agent pipelines who need accurate file and function localization before applying patches.

Frequently asked questions

What defines an "agentic" model in reinforcement learning?

Agentic models combine language understanding with sequential decision-making in interactive environments. Unlike standard LLMs that produce single responses, agentic models take actions, observe outcomes, and adapt their strategies over multiple turns. The models in this list learn these capabilities through reinforcement learning rather than pure supervised training.

How do open-source coding agents like DeepSWE-Preview compare to proprietary alternatives?

DeepSWE-Preview reported 42.2% Pass@1 and 59.0% with Hybrid Best@16 test-time scaling in July 2025. By February 2026, SWE-Master reported 61.4% and 70.8% at TTS@8, so DeepSWE's result is best presented as historically significant rather than the current open-source ceiling. Comparing any of these to a proprietary assistant requires naming the specific model and matching the scaffold and inference budget. The durable difference is control: open-weight models provide direct control over weights, self-hosting, data pipelines, and arbitrary fine-tuning on organization-specific codebases. Proprietary providers may also offer vendor-managed customization paths such as supervised fine-tuning, reinforcement fine-tuning, and custom-model programs, with availability varying by provider over time. The accurate framing is that proprietary options generally offer less infrastructure and model-level control, not that they cannot accommodate customization at all.

What infrastructure requirements exist for running these agentic RL models?

These models range from 8B to 33B parameters, requiring GPU memory from 16GB to 80GB or more depending on quantization and batch size. On Modal, developers specify the required GPU type or an ordered list of acceptable GPU types, as documented in the GPU guide; Modal then provisions and autoscales that capacity from its multi-cloud hardware pool without user-managed reservations.

Can these models be customized for specific industry applications?

Every checkpoint in this list uses a permissive open-source license, MIT for DeepSWE-Preview and Apache-2.0 for the other five, enabling modification. Teams commonly fine-tune on domain-specific tasks, though this requires appropriate training infrastructure and datasets.

How does Modal facilitate deployment of these open-source models?

Modal provides CPU and GPU infrastructure for inference and dedicated model training, secure Sandboxes for generated-code execution and RL environments, and Batch for massively parallel asynchronous processing. Modal is engineered for fast cold starts, with an optimized filesystem that helps containers come online quickly without letting large images slow startup down, and Memory Snapshots further reduce initialization work such as imports, JIT compilation, and CUDA Graph capture. Modal's code-first SDKs cover Python, TypeScript, and Go, and a Sandbox runs whatever language or runtime the workload requires. Modal also supports HIPAA-compliant workloads on Enterprise plans via a BAA for teams with regulated data.

What distinguishes RL-only agent post-training from the traditional SFT to RL pipeline?

Traditional approaches first train on supervised examples before reinforcement learning. DeepSWE-Preview demonstrates that agents can improve substantially from environment interaction without an agent-specific supervised warm-up, applied on top of an already capable pretrained and post-trained base model. The approach requires careful algorithm design and sufficient compute, and it is not the same as learning reasoning from RL alone.
