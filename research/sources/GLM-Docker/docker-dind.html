原生 Docker ​

采用 Docker-in-Docker 技术，在开发机或训练任务容器内部署一个完整的 Docker 引擎。在创建开发机时默认启用了该功能，支持通过 Docker CLI 和 Docker SDK 进行开发调用。

使用场景 ​

  • 镜像构建与推送：参考 使用 Docker 构建镜像，并将镜像推送到私有镜像仓库。
  • 启动容器应用：利用 Docker 启动容器来运行应用，模拟实际运行环境，便于进行功能测试、性能优化等操作，确保应用能稳定可靠地运行。

已知限制 ​

  • 存储资源可用性：由于开发机不建议使用本地存储，如果内部启动的容器可以考虑将开发机主容器的存储资源挂载给内部容器。
  • GPU 可用性：由于平台开发机为共享 8 卡机制，因此我们启动容器支持挂载 GPU 数量最大为 8 卡。提前确认卡被占用情况，以及及时释放该资源。
  • Docker Compose 支持：支持使用 Docker Compose 来定义和运行多容器 Docker 应用程序，但需要自行安装工具。详见 Docker Compose 使用。

docker常用命令 ​

sh
# 1. 启动容器：运行容器化应用进行测试
docker run -d -p 8080:8080 --name my-node-app my-node-app
# 参数解释：
# -d 表示让容器在后台运行；
# -p 8080:8080 用于将容器内部的 8080 端口映射到开发机的 8080 端口，便于外部访问容器内运行的服务；
# --name my-node-app 为容器指定名称，方便后续管理操作。
# my-node-app 是要运行的镜像名称，需替换为实际的镜像。

# 2. 检查容器日志
docker logs my-node-app
# 通过查看日志，可了解容器内应用运行状况，排查潜在问题。

# 3. 进入容器内部进行进一步测试
docker exec -it my-node-app /bin/bash
# 此命令能以交互方式进入正在运行的容器内部，便于执行更多命令，如查看文件系统、安装额外软件包等。

# 4. 停止并移除容器：测试完成后执行以下操作
docker stop my-node-app
docker rm my-node-app
# 先停止容器运行，再从系统中移除，释放相关资源。

容器挂载指定数量的 GPU ​

bash
docker run -it --gpus '"device=0,1"' --name my_gpu_container my_image_name

命令解释

  • -it ：表示以交互模式启动容器，这样可以进入容器内部进行操作并实时看到输出信息。
  • --gpus "device=0,1" ：这是关键参数，用于指定要挂载的 GPU 设备。在这里，"device=0,1" 表示挂载编号为 0 和 1 的两个 GPU 设备到容器中，你可以根据实际可用的 GPU 编号以及需求来调整这里的数值。例如，如果你的开发机有多个 GPU，你可以选择其中的几个进行挂载。
  • --name my_gpu_container ：给启动的容器指定一个名称为 my_gpu_container，方便后续对该容器进行管理，比如查看日志、停止、重启等操作时通过这个名称来指定容器。
  • my_image_name ：这是要运行的镜像名称，你需要将其替换为实际存在且需要在挂载 GPU 的情况下运行的镜像，比如包含了需要利用 GPU 进行计算的机器学习模型训练、深度学习推理等相关应用的镜像。

常见问题

无法拉取 Docker Hub 镜像

由于运营商网络方面的原因，在尝试拉取 Docker Hub 镜像时，可能会出现下载失败的情况。针对某些集群，可以通过配置代理的方式来尝试解决该问题。建议您在生产环境中谨慎使用依赖于 Docker Hub 的容器镜像。

如何处理镜像构建失败

倘若在开发机详情页面或者镜像中心发现镜像构建失败的提示信息，请与 @苑雄雄 联系，以便能够快速定位问题并找到有效的解决办法。

创建创建开发机、训练任务或推理服务时选用公网镜像失败

在创建开发机、训练任务或者推理服务的过程中，如果选取了公网镜像却出现创建失败的情况，大概率是由于网络不通所导致的。针对这种情况，可以考虑提前将所需的镜像迁移至私有镜像仓库，然后从私有镜像仓库中选取镜像进行相应的创建操作。
