快速开始 ​

DockerProxy 是一个轻量级代理，它将您的本地 Docker 请求（来自 CLI 或 SDK）透明地转发到一个集中式、高可用的 Docker 集群，为您提供高并发的 Docker 能力支持。

关键特性 ​

无缝集成
与原生 Docker 体验一致。
集中化与高性能
专用的外部集群处理，提供高并发支持与远超单机的处理性能。
安全隔离
支持专属任务队列，保障个人任务独立运行不受其他业务干扰。

启用 DockerProxy ​

在平台创建开发机或训练任务时，您可以通过以下步骤启用 DockerProxy 功能：

  1. 在创建配置页面中，找到 启用 Docker-Proxy 选项。
  2. 勾选【启用 DockerProxy】。
  3. 选择定运行 Docker 容器的可用区和队列，若无特殊需求，可留空使用默认设置。

完成上述操作后，即可在任务中使用 DockerProxy 功能。

验证是否启用 DockerProxy ​

执行以下命令检查 DockerProxy 是否成功启用：

shell
docker info | grep docker-proxy

队列资源控制 ​

为实现容器与其他用户容器的资源隔离，避免因资源不足导致容器启动延迟，平台对容器运行资源进行可用区和队列划分。相关权限开通可以联系运维人员协助处理。

可用区 ​

  • 平台通过划分可用区实现对 DockerProxy 服务独立部署，相互隔离。

默认队列： ​

  • 限制单用户在该队列上运行的容器总数，当前配置为 500 个。
  • 当达到或超过限制时，新的 container start 接口会返回 HTTP 400 状态码，并报告当前运行中容器的数量
    bash
      public queue limit exceedeed, current running: %d

独占队列：通过配置可以使用非公共队列运行容器 ​

独占队列为用户提供专属资源池，适用于有特定资源需求的场景。

特性说明 ​

  • 资源协商：队列资源由队列用户协商确定使用规则，不设统一数量限制
  • 权限控制：创建或启动容器时会严格检查队列使用权限
    • 如果用户没有目标队列的使用权限，接口会返回 HTTP 400 状态码
    • 错误信息格式：cannot use job_queue: %s（其中 %s 显示使用的队列 ID）
  • 示例

配置方式 ​

  • 通过容器标签指定使用的独占队列：

    • 标签键：platform.glm.ai/job-queue
    • 标签值：目标队列 ID
    • 配置命令
      bash
      docker run --label platform.glm.ai/job-queue=queue-20250812105353-xxxxx <image>

  • 通过创建开发机/训练任务时配置选择启动可用区和队列，会自动注入对应的队列标签。
