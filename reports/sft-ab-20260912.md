# Stage-1 SFT 价值判定：base vs SFT 零样本 SWE 轨迹 A/B（2026-09-12 UTC）

**问题**：SFT 学到的（Klear 格式 NLL −33%）能否兑换成 SWE 任务解决率？
**协议**：逐字重放训练时的 Klear mini-swe-agent 格式（system/`<pr_description>`/`<instructions>`/
THOUGHT+bash 块/`<returncode><output>` 观察/`MINI_SWE_AGENT_FINAL_OUTPUT` 提交标记，模板运行时
从训练 parquet 提取、往返一致性验证）；20 个 held-out SWE-Gym 任务（本地已验证 buggy/gold
环境）；冻结 gym 判分器（可信 git 索引导出 + oracle 测试恢复 + F2P/P2P）；两臂同预算
（40 步 / 1800s / 36k ctx / greedy / 同 vLLM 服务参数）。
**协议性质**：本地协议（dev 评估；不冒充任何官方 benchmark 成绩）。

## 结论

1. **SFT 的价值判定：成立**。解决率 15%→30%，且行为质量全面改善（提交纪律 10%→100%、
   格式错误 −83%、步数 −44%）。这正是阶段② GRPO 需要的初始状态：组内有奖励方差、
   轨迹规范、不浪费步数预算。
2. base 的失败模式（不提交 → 步数耗尽 → 产物垃圾）恰是 Klear 论文/PIPE 所述
   「接口熟悉度」缺位的形态；SFT 修复的正是这一层。
3. 该 20 任务集成为项目的**本地协议冻结评估集**：后续 RL/OPD 检查点在同一张表加行，
   构成三段管线的提升曲线（项目核心交付）。
